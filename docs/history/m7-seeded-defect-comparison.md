## Corpus (24 cases: 20 with blockers, 4 clean; fixed before any run)
- 12 archived first-round candidates: the 7 luna cases plus 5 whose round-1 review in a `*-rounds.json` of the self-audit-roadmap archive holds CRITICAL/MAJOR (ids listed before freezing): 10 blocker cases + 2 clean.
- 12 synthetic: 10 hand-seeded (one planted defect each; key = file, line, why it blocks) + 2 clean diffs of the same kind.
- `manifest.json` records per case the blocker COUNT and, per blocker, a category: security-boundary, state-machine or ordinary logic. Criteria count blockers, not cases; a case with several blockers can span categories. Also per case: opaque id (`c01`..`c24`), base SHA, diff SHA-256, prompt SHA-256, key-file SHA-256. Tool versions (plugin commit, coordinator commit) and the rate table go in the manifest; its hash is logged before the first run, and a later mismatch voids the case.

## Freezing and isolation
- Per case: `git archive <base>` into a fresh `git init` repo under `$TMPDIR/m7/<opaque-id>/repo/` outside every repository (case directory = `$TMPDIR/m7/<opaque-id>/`, also holding `run/` for the paired run-dir and the legacy session dir), remove the six context classes below and create one neutral clean commit bound to the original timestamp, then `git apply --index` of the diff. Check one commit only; record original `source_base_tree`, clean initial `base_tree`, and post-cleanup candidate index `tree`; diff hash = manifest diff SHA-256 (ledger `diff_sha256` for archived cases). Keys and luna/Opus review texts sit in a sealed `keys/` directory outside every arm workspace. Repo-local agent, skill and plan config (`.agents/`, `.codex/`, `.claude/`, `CLAUDE.md`, `tasks/*-plan*`, `CHANGELOG.md`) is removed identically for both arms, before the tree hash is taken: the manifest records the post-cleanup tree, and a diff touching a cleaned path (or shipping `.agents/skills/**` or `CHANGELOG.md` content) is replaced at freeze time and logged. Context files = the task text and plan stored with the ledger entry; "case start" = the base commit timestamp. Diffs and commit messages carry no `fix`/`seeded`/`R1` markers. Each arm runs with its own `CLAUDE_CONFIG_DIR`/`CODEX_HOME` and a scratch `HOME` holding only credentials (the legacy plugin loads via `--plugin-dir` at the pinned commit), so global instructions and archived session logs are unreachable and cannot bias either arm; `keys/` is `chmod 000` until grading.
- **D-b1 Transcript scan.** Isolation of case directories alone is insufficient. Every arm's transcript and tool log is scanned mechanically: each read is resolved with realpath and must be inside the case directory or an allowlist limited to the files each tool loads at runtime (legacy: `skills/`, `agents/`, `docs/protocol/`, `scripts/`; paired-session: the coordinator's own files) plus toolchain dirs; commands whose paths cannot be resolved (variables, `cd`, subshells) fail closed as violations; reading a pinned file that matches a case-changed path or its same-directory sibling is also a violation; `~/.claude`, `~/.codex`, `~/3Cats`, `keys/`, sibling case directories, `real-run/`, `.compass/results`, plugin caches and `../` escapes are violations, and so are commands that can enumerate them (`find /`, `grep -r ~`). Any hit voids that case for BOTH arms and is reported by cause and arm. Synthetic base repos must not come from any allowlisted path or repo.
- **D-b2 Tool-version grep.** Before running, the answer-key fix text (unit: the added lines of the fix, whitespace-normalized, at least 20 characters, from the ledger's next-round diff for archived cases and the human fix patch for synthetic ones; identifiers from the key mechanism; not file names, which always match) is grepped against the pinned plugin directory and the pinned coordinator commit. Hit count > 0 excludes the case before any run; the exclusion and matching lines are logged. Cases whose changed paths also exist in the pinned plugin directory are additionally flagged and reported (only the legacy arm can read that copy). Replacement cases are added before any run, never after. Voided plus excluded cases (D-b1, D-b2, infrastructure) above 4 invalidate the run.

## Two metric windows per case and arm (D-a)
- **Window 1, first review only**: source of blocker recall and false-positive blockers. Legacy: `/review-loop:execute --review-only --stop-after exec-round` (valid values: `skills/execute/references/entry.md:13-22`), handsfree. Paired-session: the harness skips PLAN review (the reviewer thread persists across PLAN and EXEC) and scores only the first EXEC review receipt (run with `--max-exec-rounds 1`; stop semantics confirmed in the fake rehearsal). Later findings never feed recall or FP. Scored text is the reviewer's raw output before orchestrator triage (legacy: the reviewer child's per-invocation `.review-loop/tmp/{session_id}-reviewer-{invocation_id}/result.txt` that `scripts/run_claude_reviewer.py` writes on a clean exit, from the first review call that exited cleanly (the protocol's one retry after `tool_uses: 0` included); paired-session: the raw reviewer answer of the first review turn). *Erratum (m7-s1, 2026-10-05):* this sentence said "the Agent-tool return in the transcript", which predates the isolated reviewer launcher: the legacy reviewer now runs as a separate `claude -p` child, not as an Agent tool call. The top-level `{session_id}-reviewer-result.txt` is overwritten by every call and is never the source. A call that did not exit cleanly writes no `result.txt` (its `stream.jsonl` and `stderr.log` stay as evidence); when no first-review call exits cleanly, that is an arm failure (no output), scored as MISS.
- **Window 2, separate run to approve-or-cap**: source of rounds-to-approve and `unresolved`. Legacy: `--stop-after before-polish`, cap 3 enforced by the harness (`soft_limit_exec` is only a prompt). Paired-session: its own cap (`--max-exec-rounds 3`). Cap reached without approve = `unresolved`. Paired-session has no frozen-diff review-start entry today (legacy `--review-only` starts at review); a paired harness starting at EXEC review is a prerequisite not designed here; without it no scored run starts.

## Symmetry (D-c)
- Plan/scope reaches the reviewer differently (legacy `--description` under Review Target, paired-session plan file); the prompt SHA-256 is stored per case x arm x window and the underlying task text is identical. Same reviewer vendor and model in both arms (legacy `reviewer: subagent` + `reviewer_model`; paired-session `--reviewer-vendor/--reviewer-model`), same reviewer effort (paired-session defaults to `medium`; pinned for legacy too and recorded in the manifest), same executor/author model (paired-session `--author-vendor claude`; default is codex), same task text and context files. The manifest also records a per-case test command and its result on the frozen tree (both arms get the same command: paired-session `--test-command`, legacy via `--description`); cases whose tests already fail on the frozen tree are reported.
- Adversarial gate and shadow OFF in both arms. Paired-session: `--adversarial-gate off --shadow off --polish-round off`. Legacy: `adversarial_gate_skip_paths: ["**"]`, `skip_quality_polish: true`, handsfree; the legacy path has no shadow. In window 1 legacy stops before Step 3.4 anyway.
- Findings from both arms are normalized by script to `{file, line, blocking, text}` before grading; `blocking` = CRITICAL/MAJOR in both arms; `line` is null in both arms (paired-session findings have none; graders locate by file and mechanism); no severity, arm, id, token or time fields, one fixed text template. Paired-session findings with `security=true` below MAJOR, or `severity: SECURITY` (blocking in its own receipt logic), are NOT blocking here; they form a separate **security-only** column. Recall is reported with and without them; legacy has none by construction, which exposes the asymmetry.
- Grading: two graders (Opus and a different-vendor model) read the code; disagreement goes to a third pass. Verdicts HIT, PARTIAL (a miss for recall), MISS; unmatched blockers FP or VALID-NOT-IN-KEY (code verified real, listed apart). Each grader also records a guess of the arm; the guess rate is reported (blinding is only partial for prose style). Archived keys come from Opus, so recall is reported separately for archived and synthetic keys. Arms alternate per case order.

## Metrics (recorded artifacts only)
- Recall = HIT blockers / key blockers, per category; FP blockers over all cases, clean cases also alone; sub-blocker findings logged, not scored.
- Round = one exec-phase reviewer verdict (legacy: session-file round records; paired-session: state `exec_reviews`). Rounds, `unresolved`, tokens and wall time come from window 2's exec loop only, timed from review start to final verdict, excluding plan phase, docs and security stages.
- Tokens/cost: paired-session = receipt `usage_requests` summed by `write_usage` (`usage.json`); legacy = `claude -p --output-format stream-json` `result.usage` plus any Codex rollout usage; for runs killed at the cap (no `result` event) usage is summed from the per-message usage in the stream instead. Verify the legacy total includes subagent tokens; if not, report and do not gate. Uncached, cached and output kept apart; a missing source voids the token metric for that case; no estimates.
- **D-d** Arm-level failures (hold, crash, cap, no output) score as MISS/`unresolved` and are never excluded. Only infrastructure failures (provider outage, disk), attributed in the log, are excluded, from both arms; more than 2 such cases invalidates the run.

## Pass criteria (evidence for the v2.10.0 switch, not the decision)
1. Paired-session recall WITHOUT security-only findings: per split, paired HIT count >= legacy HIT count - 1 and recall >= 0.75, on both archived and synthetic splits; no security-category blocker that legacy HITs and paired-session MISSes (PARTIAL counts as MISS), judged WITH security-only findings and reported both ways. One run per case and arm: descriptive, not significant.
2. Paired-session: zero FP blockers on the 4 clean cases; total FP blockers over all 24 cases not above legacy + 1.
3. Paired-session: zero `unresolved` and median rounds <= legacy median + 1 (an `unresolved` case counts as cap 3 rounds); legacy `unresolved` is reported.
4. Median per-case cost (rate table x uncached/cached/output totals) <= 1.5x legacy (only if the legacy source qualifies); wall time reported, not gated.
5. Every row traces to manifest hash, stored prompt, raw review, normalized findings and grader record. A case with an incomplete trace is excluded only if the cause is infrastructure, from both arms, inside the cap of 2; otherwise it scores as an arm failure.

## Tooling contract and real-run prerequisites (owner decisions 2026-10-04)

The following owner decisions define the offline tooling contract. They do not authorize model runs or change any delivery/review gate.

- **Original versus clean baseline.** The original tree must not remain accessible as the sole commit when it contains removed context. The tool archives the original base, removes the six context classes, and creates one neutral, timestamp-bound clean commit in `case/repo/`; the exact candidate diff is staged against it. `source_base_tree` retains the original identity, `base_tree` identifies the clean initial commit, and `tree` is the post-cleanup candidate index. A diff touching a cleaned path is refused for operator replacement before freeze, never silently rewritten.
- `m7_corpus.py INPUT_MANIFEST.json` writes `frozen-manifest.json` and `result.json` beside the opaque case directories. Use the **frozen** manifest for grading and record its hash before any run. It adds all three tree identities, the raw-byte `worktree_sha256`, the per-case key hash, `status`, and `scan_sha256` (null for an ok case, the exact scan-evidence digest for an excluded case); `result.json` also records the original input-manifest hash. Do not modify either after a run starts. `case/run/` is empty rehearsal scaffolding. Credential isolation, chmod of sealed keys and arm runtime setup remain operator steps; this script never reads or copies credentials.
- `m7_grade.py FROZEN_MANIFEST RESULT FINDINGS KEYS OUT_PREFIX [ADJUDICATION]` verifies per-case base, tree, diff, key, status and scan-evidence digest bindings; the CLI additionally checks the live one-commit repo, the exact staged diff beside RESULT, and that every indexed path on disk has its frozen raw bytes and mode (`worktree_sha256`, taken at freeze with no git filters, so skip-worktree, assume-unchanged or an eol attribute hide nothing); the only untracked paths allowed are the legacy arm's `.review-loop/` run artifacts (plan §2). This is byte/metadata verification, not authentication of who produced a receipt.
- **Mechanism decisions.** Location is a candidate filter only. A null line is accepted and candidates are found by file. Integer lines retain the manifest's frozen tolerance, but proximity never establishes mechanism equivalence. A HIT vote outside the file/location filter becomes adjudication-required for that finding, not an automatic HIT or a whole-grade abort; other findings continue to be processed and score_ready remains false. The tool does not infer equivalence by textual similarity or a reviewer-supplied class label. Without independent code-reading votes it emits `adjudication_required` and `score_ready: false`; numeric fields are provisional lower bounds and must not be presented as completed comparison scores.
- The optional adjudication document is separate from normalized reviewer findings. Its `binding` has `manifest_sha256` (exact manifest bytes), `keys_sha256` (exact key bytes), `result_sha256` and `findings_sha256` (canonical parsed JSON: sorted keys, compact separators, ASCII escaping). Its `arms[arm][case][finding_id]` holds votes. IDs are SHA-256 of canonical JSON: a seed's full key object; a finding's file and whitespace-normalized text (line omitted). The latter prevents duplicate prose moved within the tolerance window from buying more hits.
- Every vote records `grader`, `vendor`, `model`, `verdict`, `rationale`, `code_evidence`, and a `seed` ID when relevant. HIT additionally requires `mechanism_match: true` and the key's exact `category`. Two initial votes must identify Opus/Anthropic and a different vendor; vendor identity comparisons use strip + casefold. A HIT requires two agreeing mechanism decisions. Agreement decides; disagreement stays pending until a distinct third grader's vote agrees with one initial decision. Three-way disagreement remains pending. Unresolved seeds count as MISS, never HIT, in provisional lower bounds; the comparison score is not ready until adjudication is complete. A third pass cannot overturn two agreeing initial votes.
- HIT, PARTIAL and MISS retain their meaning. An unmatched finding can be FP or VALID-NOT-IN-KEY only through recorded code-reading votes. VALID-NOT-IN-KEY has no seed, retains rationale/evidence and is reported separately from recall and FP. These input records are not evidence that any model actually ran or that a producer is authentic.
- **Duplicates/invalid prose.** Exact duplicate file+normalized text is one scored finding, regardless of repeated line values; surplus copies are counted in `duplicates`, not FP or recall. Distinct findings adjudicated to the same seed also earn at most one HIT and are reported as redundant. Explicit DUPLICATE votes must reference another finding. Empty, missing or non-string text is INVALID-TEXT, cannot HIT, and counts as FP if marked blocking. One finding can credit one seed only; one seed one finding. Stable IDs/order make key permutations leave class recall unchanged.
- `voided` reason prefixes alone are insufficient. The bound adjudication document must also provide `exclusion_evidence[case]`: case/base/diff, reason, cause arm, and artifact contents plus their SHA-256. D-b1 requires transcript and tool-log bytes, and nonempty `violations` with cause, raw_input, resolution, policy_rule, artifact name and a 1-based matching line. Infrastructure requires an attributed cause and infrastructure-log bytes. These are inspection inputs, not a replacement for the D-b1 scanner: actual realpath resolution, completeness and scanner attribution still require the operator. The grader refuses missing bytes, mismatched hashes and nonexistent log references; it cannot authenticate a fabricated entire log/scan bundle.
- Corpus exclusions retain D-b2 scan input bindings, location, count and matching-unit hashes; raw answer text stays outside arm workspaces. Existing exclusion caps and arm-failure-as-MISS rules are unchanged. Replacement corpora must be frozen before either arm runs.

- **Hard prerequisite before any real M7 run (OQ5):** a real D-b1 transcript/tool-log scanner and producer authentication must be implemented and independently verified. Synthetic scan/vote fixtures and matching digests do not satisfy this prerequisite. Both components are implemented offline (section below). The scanner is v2 ([m7-scanner-v2.md](m7-scanner-v2.md), D04), and it scans the four real m7-s4 arm transcripts with zero violations. Before a scored run, the step-5 rehearsal must still scan real transcripts of both arms, including Codex events and executor rounds.
- Every git call on a case repo (the freeze and the grader's workspace check) runs without inherited `GIT_*` variables, system or global git config, init templates or hooks (m7-s1). Otherwise a user's `init.templateDir` could plant hooks in the case repo, and `diff.noprefix` or `apply.whitespace` could change the frozen bytes. The case repo therefore has no `.git/info/`; the harness creates it before it writes `.git/info/exclude` (plan §2).
- The clean commit stages the archived files left after the cleanup with `git add -A --force` (m7-s1b), so
  `.gitignore` cannot filter them a second time. A file the base tracks that also matches `.gitignore` therefore stays
  in `base_tree`; it is not left on disk as an ignored file (poker-news-bot c06/c19). The archive itself still follows
  the base's `export-ignore` and `export-subst` attributes, so `base_tree` can differ from `source_base_tree` for such a
  base; both are recorded. The freeze also refuses an `out_root` or `key_path` under any
  `.compass/results` directory, as it refuses `~/3Cats` and git repositories: the D-b1 scan denies those paths, so every
  read of such a case would void it (m7-s4 pilot).
- A manifest frozen before this contract lacks `source_base_tree`, `base_tree`, `status`, `scan_sha256` and `worktree_sha256`. The grader refuses it, so re-freeze before any real run.
- A result cannot add, remove or change a frozen case exclusion: status and scan digest must equal the frozen manifest. An excluded scan must also pass its existing structural and case/base/diff checks. Rewriting both the manifest and result is outside byte-binding protection; the operator must retain the independently recorded pre-run manifest hash.

## Scanner, receipts and collector (m7-s3, scanner v2)

Standard-library Python 3.9 scripts. No provider call; every number from them stays unscored until real runs are
authorised.

- **D-b1 scanner.** `scripts/m7_scan.py POLICY OUT` (with `scripts/m7_shell.py`) implements
  [m7-scanner-v2.md](m7-scanner-v2.md). The threat model is in its §2, the owner rule of 2026-10-06: users and models are
  benign, and the scan catches realistic accidental crossings without excluding normal transcripts.
  - It extracts every tool call from Claude stream-json (subagents included) and Codex events.
  - Bash commands are resolved boundedly within one call: known values, segments and opaque values, plus the supported
    subset.
  - The regression corpus `tests/fixtures/m7-scan-corpus/` (the four real m7-s4 arms) must scan CLEAN, and the §5
    controls must hit (`paired_session/test_m7_scan_corpus.py`).
  - `m7_scan.py --census FILE...` counts fail-closed constructs on further real transcripts. The census is ungated.
  - `exclusion_evidence()` turns a VIOLATION into m7_grade's `exclusion_evidence[case]`. It carries the raw text and
    file digest of every scanned transcript (re-read and checked against the scan), plus the scanner's per-call
    `tool_log`.
- **Producer receipts (OQ5).** `m7_collect.py keygen` writes a per-run 32-byte secret (mode 0600, outside every
  repository, case and arm). Right after each arm run, the harness signs an HMAC-SHA256 receipt. The receipt binds the
  case, arm, window, frozen manifest hash, base and diff to:
  - the SHA-256 of every collected artifact;
  - the provider session/message/thread ids found in the streams;
  - the D-b1 scan status and digest.

  `arm_receipt()` signs only when the scan covers exactly these bytes. Grader records are signed the same way and carry
  the manifest and findings digests they graded.
  - `findings_document()` accepts only authentic receipts of this frozen manifest, this window and each case's frozen
    base and diff. It re-checks every signed artifact's bytes.
  - `adjudication()` accepts only authentic grader records bound to this manifest and findings document.
  - A receipt shows that the holder of the secret registered these bytes. It does not show that a provider produced
    them, and it cannot catch a harness that lies when signing.
- **Legacy source.** `legacy_first_review()` reads the launcher summaries, in order, from the orchestrator's own
  stream-json tool results. It takes the per-invocation `result.txt` of the first summary with status `ok`.
- **Normaliser.** Both arms become `{file, line: null, blocking, security_only, text}`, with the text
  `<summary>\nScenario: <scenario>`.
  - Legacy: `[CRITICAL]` is blocking. A text that breaks the reviewer schema is an arm failure, never an empty success.
  - Paired: CRITICAL and MAJOR are blocking; SECURITY, or `security` below MAJOR, is security-only.
- **Grader records.** One signed record per grader, case and blinded arm label. `adjudication()` maps the labels back
  and requires exactly two initial votes plus at most one third pass per finding.
- **Rehearsal.** `paired_session/test_m7_collect.py` runs the legacy side and the collector on the fake, end to end:
  freeze, the real reviewer launcher with a fake `claude`, scan, sign, normalise, grade. It also checks that forged,
  edited or replayed receipts are refused.
