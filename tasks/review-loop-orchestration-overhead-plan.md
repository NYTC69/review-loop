## Slice 1 — P1 content-bound evidence + P3 current review packet

### Design

- **Two new canonical session sections** in the single locked `{uuid}.md`:
  - `## Current Review Packet` — inserted directly after `## Approved Plan`.
  - `## Evidence Ledger` — one fenced JSON block, inserted before `## Session Metadata` (which stays last). Orchestrator is the only writer; every write goes through `scripts/evidence_ledger.py` (mandatory production entry point, Decision 1).
  - Canonical order becomes 12 sections; the entry-mode initialization table gains both rows. No second history file.

#### Evidence record (C1)

Fields: `id` (monotonic integer, append order), `claim_id`, `check`, `stage`, `disposition`, `result`, `head`, `inputs`, `deps`, `closure`, `env`, `freshness`, `assumptions[]`, `unresolved[]`, `provenance`, `author_route`, `superseded_by`.

- `claim_id` = `<check>` + `:` + scope key. Scope key is the sorted, `|`-joined list of review-target paths for `reviewer_approve` / `gate` / `agent_review:*` / `simplify`; the command line for `tests` / `lint` / `static_analysis`; the literal `session` for `docs_consistency` / `security_scan`; the free-text description for `manual:<desc>`. Two records with the same `claim_id` are checks of the same claim.
- `disposition ∈ {executed, not-applicable, controlled-skip}`. `result ∈ {PASS, FAIL}` is required iff `disposition = executed` and must be absent otherwise. `not-applicable` carries a `reason` (e.g. no static analyzer configured); `controlled-skip` carries the gate SKIP reason verbatim (the `adversarial-gate: SKIP reason=… detail=…` banner emitted by `scripts/adversarial_gate_invoke.py`, or the orchestrator's `skipped-by-config` from the `adversarial_gate_skip_paths` rule) and is only legal for `check = gate`. Neither is a PASS; each satisfies its stage requirement only where the protocol already allows N/A or controlled SKIP today (3.5.2 static analysis; Step 3.4 controlled SKIP). No other check may use them.
- `inputs {path: blob_sha | "<deleted>" | "<untracked:blob_sha>"}`, `deps {path: blob_sha} | "uncertain"`, and `selectors[]`. Each selector is `{kind: glob | dir | discovery, pattern, members_digest}` where `members_digest` = sha256 over the sorted `(path, blob_sha)` pairs currently matching `pattern` in the snapshot tree (tracked and in-scope untracked alike). `closure ∈ {declared, uncertain}`: `declared` means the orchestrator asserts `inputs ∪ deps ∪ selectors` is the complete relevant dependency closure of this check; anything else is `uncertain`. Blob identities are the stored blobs of the snapshot (see §Snapshots), so staged / unstaged / untracked states hash the same bytes; renames and copies are recorded as the new path plus a `<deleted>` tombstone for the old path (from `git status --porcelain=v2 -z`).
- **Discovery-based checks must declare selectors, not just files** (C1): `tests` (e.g. `tests/**`, `conftest.py`, `pytest.ini` / `pyproject.toml`), `lint` (every contract glob plus the contract files), `static_analysis` and `security_scan` (their configured roots), and `reviewer_approve` / `gate` / `agent_review:*` whenever the review target is a directory. Enumerated files alone are permitted only when the check's inputs are explicit file arguments. A closure that cannot be stated as files + selectors is `uncertain`. A member that newly matches, stops matching, is removed, or is renamed changes `members_digest` and invalidates the claim at `check` time; no fixed path exceptions exist.
- `env {command, recorded_at}` is required for `tests`, `lint`, `static_analysis`, `security_scan`, `manual:*`. `freshness` is required for `manual:*` and for any record the orchestrator marks environment-sensitive: `{"kind": "ttl", "seconds": N}` or `{"kind": "bound-to-head"}`. **A record that requires `freshness` and lacks it is non-reusable** (fails validity, never a schema error — it still counts as executed for the round it was produced in).
- `provenance ∈ {"fresh", "reused-from:<id>"}` plus a mandatory `why` sentence for reuse. `author_route ∈ {executor, orchestrator-direct, n/a}`.

#### Active-record rule (C1) — deterministic, implemented in `evidence_ledger.py check`

1. For each `claim_id`, the **active** record is the one with the highest `id`. All lower-`id` records for that claim get `superseded_by = <active id>` on the next ledger write; they are never consulted for stage derivation.
2. A stage is present iff every required claim for that stage has an active record that is **valid**. Valid ⇔ (`disposition = executed ∧ result = PASS` ∨ `disposition ∈ {not-applicable, controlled-skip}` where permitted) ∧ `closure = declared` ∧ `deps ≠ "uncertain"` ∧ every `inputs` / `deps` entry is byte-identical to the current worktree (tombstones must still be absent; untracked blobs must still match) ∧ `unresolved = []` ∧ freshness holds (`ttl` not expired against `recorded_at`; `bound-to-head` requires `head` = current `HEAD`).
3. **Failure dominance**: an active `FAIL` keeps the claim unsatisfied until a *new* record with a higher `id` and `result = PASS` is appended. A prior PASS can never satisfy a claim after a later FAIL, because it is superseded by construction.
4. A `FAIL`, an `uncertain` closure, an unresolved finding, or an expired freshness is never reused; `provenance = reused-from` is only legal when the source record is currently valid under rule 2.
5. Anything not covered by rules 1–4 → the claim is unsatisfied → relevant rerun. Prefer rerun over argument.

- **Required claim sets per stage**:
  - `exec` = `reviewer_approve` (executed PASS) + `gate` (executed PASS or `controlled-skip`).
  - `polish` = `static_analysis` (executed PASS or `not-applicable`), `agent_review:code-reviewer`, `agent_review:silent-failure-hunter`, `simplify`, `tests`.
  - `docs` = `docs_consistency`. `security` = `security_scan`.
  - `completed_stages` is derived from the ledger at every write boundary (after any Executor / orchestrator-direct / simplifier / doc / `.gitignore` write, and at drift check) by `evidence_ledger.py check`; the orchestrator never hand-edits it.
  - The six all-clear invalidation rules collapse to: drift acceptance and baseline backfill still clear everything (external provenance = uncertain); every other write invalidates per record through rule 2.

#### Convergence rule (C2) — dependency-closure proof, no path categories

- After a write, `evidence_ledger.py classify` computes the changed-path set (porcelain v2 vs the last snapshot) and, for each active record required by `exec`, checks whether any changed path is in that record's `inputs ∪ deps`, or whether the record has `closure = uncertain`. If **no** `exec`-required record is touched and all have `closure = declared`, the delta is **non-invalidating for exec**; otherwise `exec` is invalidated.
- Positive proof only: there is no "prose-looking", extension, directory, or path-category rule anywhere. Today's prose-only fast-replay precedent is re-expressed as: the orchestrator declared, at approval time, the review-target paths plus reviewer- or Executor-named dependencies as the `reviewer_approve` closure; a later write outside that closure is non-invalidating **only because** the closure was declared complete. If the orchestrator cannot enumerate the closure it records `closure = uncertain`, and every later write invalidates `exec`.
- The `lint` claim's closure is emitted by `evidence_ledger.py lint-closure` as selectors: `tests/skills/contracts/**`, the runner's own discovery roots in `scripts/run-skill-lint` (`docs/protocol/*.md`; every `SKILL.md` under `skills/` and `.agents/skills/`; `tests/skills/smoke/*.json`), one selector per `file` / glob a contract JSON references, plus `scripts/run-skill-lint` itself as an input. Digests are recomputed at every `check`, so a new skill file matching a contract glob, or a new contract, invalidates `lint` by closure, not by path category.
- A delta that invalidates `exec` starts a new execution convergence → Step 3 round → independent Reviewer → Step 3.4 runs once, unconditionally. A non-invalidating delta → reviewer-only incremental replay of the touched non-exec claims, no new convergence, no gate. No line-count skip anywhere.

#### Snapshots (round-2 C2) — retrievable content, not bare hashes

- At every write boundary `evidence_ledger.py snapshot` stores content, not just identities: for each in-scope path (all tracked paths plus untracked, non-ignored paths inside the declared scope) it runs `git hash-object -w`, builds a tree through a private index file (`GIT_INDEX_FILE=$(git rev-parse --git-dir)/review-loop/{uuid}.index` — resolved, not hard-coded `.git/`, because linked worktrees have a `.git` file; populated with `git update-index --add --cacheinfo <mode>,<blob>,<path>`, then `git write-tree`), and records a parentless commit with `git commit-tree` (explicit `GIT_AUTHOR_*` / `GIT_COMMITTER_*` env so the helper never depends on user identity config) under `refs/review-loop/{uuid}/snap/{n}` via `git update-ref`. The worktree, the user's index, `HEAD`, and branches are untouched; the objects stay reachable and are never pruned by gc while the ref exists.
- Snapshot `n` is referenced by ledger records (`snapshot: n`) and by the packet. `inputs` / `deps` blob identities are verified against the snapshot tree, and the attributable patch is materialized as `git diff refs/…/snap/{pre} refs/…/snap/{post} -- <scope paths>`; hashes verify the patch, they are not the patch.
- **Legacy / first initialization**: snap/0 is the current verified worktree state (tracked dirty and in-scope untracked content included). All pre-existing dirty content lives in snap/0 and is never attributed to the task; the first round's delta is snap/0 → snap/1. Evidence is re-earned; `HEAD`-to-dirty differences are never treated as the task delta. The existing dirty map still marks unrelated dirty paths as excluded.
- **Fail-closed when a snapshot cannot be stored** (read-only `.git`, sandboxed Codex run): the Codex Stage 1 orchestrator runs `evidence_ledger.py snapshot` / `record` **outside** the Codex sandbox, under the same rule the Codex mirrors already apply to the `claude -p` reviewer command (the workspace-write sandbox denies `.git` writes); if that is not possible, no record may be appended, every claim stays `uncertain`, the direct author route is refused, and the reviewer prompt states `delta: unattributable — reviewing worktree diff against the last stored snapshot`. Refs are kept for audit; `evidence_ledger.py prune --session <uuid>` deletes them only when the user asks.

#### Packet (round-1 C3) — semantic boundedness, attributable delta

- `## Current Review Packet` is rewritten in full each round. **Required fields are never truncated or moved to history**: current intent + acceptance criteria (full text); binding decisions and authorization (full text of every ruling still in force); exact delta; touched contracts / invariants; evidence table (ledger ids, disposition, fresh/reused, provenance `why`); unresolved findings + author response; declared deviations; risks / open questions; author route. No line cap. Boundedness is semantic: only *supporting* detail (prior-round transcripts, superseded findings, resolved discussions) is referenced into `## Review History` by entry id.
- **Exact delta** = `git diff --stat` (navigation only) **plus** a `### Attributable Delta` table: `snapshot pre | snapshot post | path | pre_blob | post_blob`. `pre` is the snapshot the previous packet was reviewed at (snap/0 for a first round), **never** `HEAD`; so a file that was already dirty before this round attributes only this round's change. Materialization is deterministic and retrievable: `scripts/evidence_ledger.py delta --session <uuid>` runs `git diff` between the two stored snapshot commits restricted to the scope paths, and verifies each hunk's pre/post blob against the table. Reviewer prompts point at that command; findings are anchored to the materialized patch, which satisfies "findings traceable to the exact diff reviewed" and the dirty-work invariant. Unrelated dirty paths never appear in the table.
- Applies to **planning rounds too** (replaces the flat all-rounds findings dump at `planning.md:234-241`); the delta for a planning round is the plan-text diff between rounds.
- **Reviewer prompts** (both runtimes, planning + execution): "Read `## Current Review Packet` first. Load a `## Review History` entry only when the packet references it or a claim needs provenance. Absence of irrelevant history is not a defect." Old sessions without a ledger fail closed: empty stages, snap/0 taken from the current verified worktree, fresh packet whose first delta is snap/0 → snap/1, rerun affected checks; never reinterpret "passed earlier" prose as PASS.

#### Timing Log (MINOR; production home of the Slice 4 measurement fields)

Header becomes `Phase | Round | Role | Duration | Dispatch | Reuse | Reads | Unchanged | Tests | Pause | Model | Tokens | Cost` — the per-step overhead subset of the Slice 4 field set (Slice 4 §Mandatory measurement fields): `Duration` ↔ `elapsed_s`, `Dispatch` ↔ `executor_dispatches` / `reviewer_dispatches` / `gate_runs`, `Reuse` ↔ `reuse[]`, `Reads` ↔ `repeated_reads` / `history_entries_total`, `Unchanged` ↔ `unchanged_content_reviewed` / `unchanged_lines_reviewed`, `Tests` ↔ `tests_rerun` / `tests_reused`, `Pause` ↔ `user_pauses[]`, `Model` ↔ `model`, `Tokens` ↔ `tokens_in` / `tokens_out`, `Cost` ↔ `cost_usd`. The Slice 4 fields with **no** production column are the per-case evaluation-only fields `defects_found`, `defects_missed`, `theoretical_complexity_added`, `blocking_rejected_or_downgraded`, `stale_evidence_reused` (they need seeded ground truth or a whole-case view, which a live session does not have); the equivalence claim is exactly this subset, not the full set. Per row: `Duration` = wall-clock from `loop_state.timing.steps` (`N/A` when not recorded); `Dispatch` = `executor:n reviewer:n gate:n` for the row's step; `Reuse` = `reused:n rerun:n` plus each reused claim's ledger id and its `why` (from `evidence_ledger.py check`); `Reads` = `## Review History` entries presented to the Reviewer this round / total entries (packet-referenced only under the new rule); `Unchanged` = review-scope paths whose pre and post snapshot blobs are identical (presented to the Reviewer but absent from the Attributable Delta); `Tests` = `rerun` or `reused` with `inputs_changed: true|false`; `Pause` = `none` or the pause kind (`product | risk | scope | authorization | other`); `Model` and `Tokens` from Agent / reviewer metadata (`loop_state.token_usage`) when present, else `N/A`; `Cost` = USD from the same metadata (`total_cost_usd` of a `claude -p --output-format json` envelope, or an Agent-tool cost field) when present, else `N/A`. On the first write under the new header every existing four-column row is rewritten with `N/A` in each new column; the table is always rectangular. Never invent a value: any unmeasured cell is `N/A`.

2. **Next Step 3 round.** Ordinary round steps apply with one deterministic branch on the partition result:

## Decided (not open)

Round-1 rulings, adopted verbatim:

1. **Helper scripts** — `scripts/evidence_ledger.py` + `scripts/finding_triage.py` are mandatory production entry points for both runtimes; they reuse canonical git-state semantics (staged, unstaged, untracked, renamed, copied, deleted via porcelain v2 + `git hash-object`) and never classify semantic impact from paths.
2. **Rubric enforcement** — mandatory post-parse semantic validation for every blocking normal or adversarial finding; missing fields request corrected review output, never a code change. Severity vocabulary stays `[CRITICAL]` / `[MINOR]`; verdicts are never overridden.
3. **Evaluation evidence** — deterministic eight-case harness driven by production helpers for structural before/after, plus mandatory targeted Opus Reviewer smoke for cases 6 and 7; no full live workflows; unrunnable smoke = `unverified`.
4. **Dependency closure** — orchestrator-owned declaration (files + selectors with membership digests) with `closure = uncertain` / `deps = "uncertain"` as the fail-closed default; Executor schema unchanged; the DIR separately carries its own `### Verification`.

Round-2 rulings, adopted:

5. **Selectors, not enumerations** — discovery-based checks declare selectors whose membership digests are recomputed at validation; new / removed / renamed members invalidate; no fixed path exceptions.
6. **Stored snapshots** — content is stored (`hash-object -w` + `commit-tree` + `refs/review-loop/{uuid}/snap/{n}`); hash-only identities are insufficient; legacy sessions baseline at snap/0 of the current verified worktree.
7. **Affirmative eligibility** — direct authorship requires every eligibility fact `true`, not merely all sensitive flags `false`.
8. **Case 6 pass rule** — live smoke passes only on APPROVE or MINOR-only; an incomplete CRITICAL is a failed / unverified smoke; deterministic coverage goes through dispute → concurrence.

## Open questions for round 3

None that block implementation. Two implementation-time disclosures:

- Snapshot storage adds objects to `.git` for every write boundary of a session. Sizes are bounded by the in-scope content (deduplicated by git); `prune` exists but is never automatic.
