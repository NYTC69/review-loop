**Row 4b, P0-4: two ways to skip a fresh probe on the real CLI.** `--skip-probe` stays fake-harness only. (1) `--accept-probe-skip --reason TEXT` (the flag is command line only, never restored from state or config) lets `run`/`resume`/`reject` proceed without a passing `permission-probe.json`; it is recorded in `state.json` (actor, reason, UTC time, reviewer and author flags digests) and later commands honour that record until either digest changes or a `permission-probe` re-runs, which voids it for good. (2) A passing probe is cached automatically: only a status of exactly `PASS` is written to `~/.cache/review-loop/probe-pass/<key>.json` (dir 0700, file 0600; the key is sha256 of the probe surface version, both flags digests and the `claude --version` when a role is Claude), and a later run with the same key reuses it (recorded as `reused_from`) only when the run has no report of its own and its last probe completed, and when no path component is a symlink, the file is a regular file owned by the user and not group/world-writable, its recorded key and key inputs match, it passes `probe_passed()` for the run and it is at most 7 days old. Neither replaces the Codex CLI contract check (P0-2) or the Claude author gate (P0-3), which need their own pass or opt-in; the fake harness never reads or writes the cache; no role can write it (Claude author Edit deny and Bash `denyWrite`, the Codex author sandbox roots exclude it). Because the digests bind the run dir today (Claude sandbox and OS-probe paths, the Codex author temp dir), an entry is in practice reused by the same run dir only.
