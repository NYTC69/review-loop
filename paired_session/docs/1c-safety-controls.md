**Row 4b, P0-4: two ways to skip a fresh probe on the real CLI.** `--skip-probe` stays fake-harness only. (1) `--accept-probe-skip --reason TEXT` (the flag is command line only, never restored from state or config) lets `run`/`resume`/`reject` proceed without a passing `permission-probe.json`; it is recorded in `state.json` (actor, reason, UTC time, reviewer and author flags digests) and later commands honour that record until either digest changes or a `permission-probe` re-runs, which voids it for good. (2) A passing probe is cached automatically: only a status of exactly `PASS` is written to `~/.cache/review-loop/probe-pass/<key>.json` (dir 0700, file 0600; the key is sha256 of the probe surface version, both flags digests and the `claude --version` when a role is Claude), and a later run with the same key reuses it (recorded as `reused_from`) only when the run has no report of its own and its last probe completed, and when no path component is a symlink, the file is a regular file owned by the user and not group/world-writable, its recorded key and key inputs match, it passes `probe_passed()` for the run and it is at most 7 days old. Neither replaces the Codex CLI contract check (P0-2) or the Claude author gate (P0-3), which need their own pass or opt-in; the fake harness never reads or writes the cache; no role can write it (Claude author Edit deny and Bash `denyWrite`, the Codex author sandbox roots exclude it). Because the digests bind the run dir today (Claude sandbox and OS-probe paths, the Codex author temp dir), an entry is in practice reused by the same run dir only. F4: when a probe of the same key ends with any status other than PASS (FAIL, UNKNOWN, PASS_RESIDUAL_RISK) and an entry for that key exists, the entry is replaced by a tombstone (same file name and the same private-dir and symlink checks as the write path; fields `key`, `key_inputs`, `status: VOID`, the voiding `run_dir`, `source_report_sha256`, `time`) and reuse is refused with `probe cache: voided by a later non-PASS probe (<time>, <run_dir>)`; a later real PASS overwrites the tombstone. If the tombstone cannot be written the entry is deleted instead (noted in the report `warning`); if that fails too, the report `warning` and stdout say `PROBE CACHE ENTRY NOT VOIDED` and name the path. The verdict never changes. No void-failure marker in run state is needed: a run that has probed never consults the cache, and another run does not read this run's state.

**Row 4c, G-a: the gate's vendor is probed.** `gate_flags()` / `gate_flags_digest()` (built with the reviewer's builder, gate vendor/model/effort/binary/commands/sandbox, OS-only path of the `gate-probe` role) are recorded in `permission-probe.json` next to `gate_permission_probe`. When the gate vendor differs from the reviewer's, `permission-probe` runs a second fresh read-only turn as role `gate-probe` (the gate's vendor, model and read-only argv; same prompt, seven write attempts, snapshot check and, for a Claude gate, the /tmp, run_dir, context and own OS-only denial checks); the report status is the worse of the two turns. When the vendors are equal there is no second turn and `gate_permission_probe` is `NOT_NEEDED`. `probe_passed` requires the report's `gate_flags_digest` to equal the current one (a report made before G-a has none and does not pass on the real CLI: re-run `permission-probe` once) and, for a different gate vendor, a passing `gate_permission_probe`. The probe-skip acceptance record and the probe-pass cache key bind `gate_flags_digest` too, so a gate flag change voids the acceptance and misses the cache.
