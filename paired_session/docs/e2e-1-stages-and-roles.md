## Stage machine

After a normal EXEC reviewer APPROVE, the existing Step 3.4 gate must be spent or resolved for that **convergence** before FINISH. The sequence is `FINISH → POLISH-Q → DOCS → SECURITY → DELIVERY → CLOSE`. Operator `accept` occurs after SECURITY and before DELIVERY; ordinary `reject` starts a new EXEC convergence. `reject --scope-change` stays refused until 2C part 3 exists, then returns to PLAN and requires new approval. No stage infers success from a later stage, report or previous run. Each stage persists its own status and coordinator-written receipt before the next transition. Missing evidence, stale tree/plan identity, an unresolved blocking finding, failed required checks, exhausted budget or an unsafe write HOLDs.

| Stage | Entry | Exit | HOLD / invalidation |
|---|---|---|---|
| FINISH | EXEC reviewer APPROVE plus same-convergence Step 3.4 gate resolution; no open blocker | Separate finisher executor proposes readiness; coordinator writes/validates the bounded receipt, edits and configured tests; FINISH itself is not an approval gate | Missing gate/receipt, failed test, or an EXEC-invalidating write; replay EXEC review/new convergence gate before downstream work |
| POLISH-Q | Current FINISH receipt and EXEC evidence | Required language specialists, code/silent-failure reviewers, simplifier, and test analyzer have valid receipts; blocking findings closed by a fresh re-review from their source role | Missing tool-use or review evidence, failed test, open blocker, unsafe writer path, or exhausted fix/review budget |
| DOCS | Current POLISH-Q receipt | Always run code-comment consistency; configured `docs_file`/CHANGELOG work, fresh docs review and required retest pass | Stale/false docs, missing review/test evidence, or an EXEC-invalidating write; specifics in doc 3 |
| SECURITY | Current DOCS receipt and candidate tree | Full sensitive-file preflight plus fresh security review and any fix/re-review pass succeed on the delivery candidate | Secret, unresolved security finding, failed check, or changed tree; specifics in doc 3 |
| DELIVERY | SECURITY passed on candidate tree and explicit operator acceptance of that tree | One verified **local** product commit with persisted intent/receipt | Tree, index, receipt, test or acceptance mismatch; external merge/push/cleanup remain off by default; doc 4 |
| CLOSE | Verified product SHA and explicit Compass item reference | Local Compass close evidence and terminal run status | Ambiguous item, stale BACKLOG or incomplete close receipt; doc 4 |

This retains legacy `docs/protocol/execution.md` Step 3.4, Step 3.5, Step 3.6, Step 3.7 and Step 4 in order. Step 3.7 remains unconditional even for a no-op change (§Step 3.7); Step 3.5 specialists and the `tool_uses: 0` discard/retry guard remain required (§Quality-agent tool-use guard, §Step 3.5). `DONE` after SECURITY means pending 2C operator acceptance, never accepted or closed. A post-SECURITY reject invalidates the downstream receipts and starts EXEC again; the exact acceptance/commit contract is doc 4.

## Ownership and evidence

- The **coordinator** dispatches every finisher, specialist, docs and security call; chooses read/write capability and fixed model/prompt inputs; writes invocation/tool-use/test/receipt evidence; runs `test_command`; verifies snapshots; and alone advances stages and finding-ledger status/severity. A missing `test_command` cannot silently satisfy a required check. It never treats an agent's self-reported test as observed execution. This implements R12-4 R1 C1 and `docs/protocol/execution.md` §Step 3.5.3–3.5.5.
- The **finisher** is a separate executor identity/session from the EXEC author. It may edit only authorized product candidate paths and report proposed readiness/fixes. It never dispatches its own reviewers, runs the authoritative test, writes a receipt/ledger, grades findings, or changes a stage. The coordinator routes POLISH-Q, DOCS and SECURITY repairs back to this finisher (or a separate path-limited specialist writer), then re-dispatches the finding's source reviewer. A downstream code edit returns to EXEC review under the invalidation rule below.
- The coordinator inlines the relevant `agents/*.md` body for every specialist call, following legacy `general-purpose` + inlined-body dispatch in `docs/protocol/execution.md` §Step 3.5.2–3.5.5 and `skills/review-pr/SKILL.md` §Step 3 — Launch Review Agents. Claude roles run through `claude -p`; Codex roles run through `codex exec` with the same body, never a plugin agent type. Reviewer calls are read-only. A specialist finding closes only by a **new review from that same role** receiving its own finding text and recording explicit disposition; mere silence is not closure. The Step 3.4 gate is the explicit exception: its findings are disposed by the normal EXEC reviewer after the gate's single pass. Writer self-reports/readiness and disposition proposals are never passed as reviewer evidence; reviewers see the candidate diff and their own prior findings only. No writer can downgrade a finding.
- Freeze role vendor/model at run start. Roles are operator-configured (ADR-9); the per-vendor defaults are `claude-opus-5-5` and `gpt-6.1-sol` (ADR-12; the ADR-8 Codex pin was `gpt-6-luna`). EXEC author and separate FINISH/DOCS/SECURITY fixers use the configured author vendor/model; persistent EXEC reviewer, shadow, POLISH-Q language/code/test reviewers, docs reviewer and fresh security reviewer use the configured reviewer vendor/model; Step 3.4 gate uses the author's vendor by default (ADR-10; an explicit `--gate-vendor` overrides it and is recorded as `gate_vendor_source: operator`; a saved run without `gate_vendor` keeps the old opposite-author derivation) and that vendor's default model unless configured. POLISH-Q simplifier/test writer uses author vendor/model in a separate session. Author and reviewer may share a vendor exactly as in real EXEC (ADR-11 D-8 replaces the earlier rule that lifecycle activation rejects it). Changing a default model needs an ADR; the Round 13 development executor choice is not a separate product-model authority. See `DECISIONS.md` ADR-9/ADR-10/ADR-11 and `paired_session/coordinator.py` `_role_vendor`/`_model_effort`.
- Fresh shadow, gate, POLISH-Q specialists, docs and security reviewers receive only the approved plan, current candidate/delta, role-specific prior findings for disposition when applicable, and necessary work item context. They cannot read other roles' transcript, ledger, verdicts or report, and cannot write candidate, run dir or global state. Persistent reviewer context stays separate. Coordinator audits actual input/tool traces; prompt instructions alone are insufficient (R12-4 R1 M6 and R2 M4).
- The coordinator applies the legacy `tool_uses: 0` guard to quality, docs and security calls: discard and retry once; a second zero-tool result cannot pass the stage (`execution.md` §Quality-agent tool-use guard). New reviewer roles have bounded per-stage and whole-item invocations; exact arithmetic and replay budgets are doc 2 (R12-4 R1 M4 / R2 M3).

## Writes and EXEC invalidation

An EXEC review receipt identifies its complete **changed/closure** path set and inputs with tree identity, including adds, deletions, renames, mode changes, symlinks and index-only removals. Any later write to an EXEC-reviewed path/closure input, **or any path outside a narrow docs allowlist**, invalidates EXEC and returns to the normal EXEC reviewer plus the **new** convergence's gate; FINISH, POLISH-Q, DOCS and SECURITY then rerun. This includes comments/docstrings, tests, generated files, manifests, config and `.gitignore`; no semantic shortcut. A docs-allowlisted write is non-invalidating only when disjoint from the reviewed set. Any SECURITY-stage write, even to an allowlisted doc, invalidates EXEC and replays all downstream stages, preserving legacy Step 3.7's stronger boundary. This implements R12-4 R1 C2 and legacy `execution.md` §Step 3.6 write-boundary replay and §Step 3.7 write invalidation.

The docs allowlist is an **explicit exact-path list** in project config, resolved and frozen at run start against the candidate tree (globs expand once). Default: empty **except** the exact configured `docs_file`, which the coordinator admits deterministically at start if it is a safe in-tree documentation path and not an EXEC changed/closure input; otherwise preflight HOLDs before EXEC approval. Known code, config, manifest, test, `.gitignore`, `.git` and symlink-escape paths are never admitted. These reserved docs paths are writable only by DOCS, excluded from EXEC author/FINISH/POLISH write grants and from the EXEC changed/closure target set; any attempted writer edit refuses/HOLDs before review. A new convergence keeps the same frozen reservation, so DOCS can update its entry without invalidating EXEC; docs reviewer and SECURITY review the final candidate. If the EXEC author already changed the configured `docs_file`, preflight refuses until that edit moves to DOCS; it never enters a replay loop. Any DOCS out-of-allowlist write refuses/HOLDs; any authorized code repair by finisher separately invalidates EXEC. Any docs write reruns configured test/lint before SECURITY (R12-4 R2 M8; R1 S2).

| Writing role | Allowed write target | Boundary |
|---|---|---|
| EXEC author | Authorized product candidate paths in EXEC; no run artifacts | Normal EXEC reviewer/gate on its diff |
| FINISH executor | Authorized candidate paths only | Any EXEC-reviewed/non-docs path invalidates EXEC |
| POLISH-Q simplifier or test writer | Coordinator-granted candidate paths for that call only | Same invalidation; no direct ledger/receipt writes |
| DOCS writer | Exact docs allowlist only | Out-of-allowlist write refuses/HOLDs; authorized finisher code repair separately invalidates EXEC; rerun required checks |
| SECURITY fixer | Explicit candidate repair paths only; never silent `.gitignore` writes | **Every** SECURITY write invalidates EXEC and downstream receipts; doc 3 handles sensitive paths |

Every writer's OS sandbox denies writes to `run_dir` (including evidence, receipts and state), `.git`, other workspace roots, credentials and global config; the coordinator rejects any tool trace escaping the granted candidate paths and HOLDs. A writer cannot call `accept`, commit or close. Reviewer sandboxes are read-only and cannot see those run artifacts. Freeze lifecycle enablement, exact docs allowlist, skip globs, `skip_quality_polish`, role models and `docs_file` into saved config at run start; resume compares them. Also read every `agents/*.md` body and gate prompt from the support-repo root at start, record hashes in receipts and HOLD before dispatch if any hash changes, including self-hosted runs. Writer edits to either `.review-loop/paired-session.json` or `.review-loop/config.md` HOLD; they never expand grants or change review prompts mid-run. The exact candidate materialization and OS permissions are doc 2; until enforceable, lifecycle activation fails closed (R12-4 R2 M11, R1 S4).

## Gate, severity, switches and old state

`gate_ran` means **one gate invocation per EXEC convergence**, not “APPROVE for every later digest.” A gate APPROVE proceeds only with no mapped blocking finding. Any mapped blocker, including MEDIUM, is treated as REQUEST_CHANGES regardless of adapter verdict; ordinary EXEC repair and normal reviewer explicit disposition may close it without re-invoking that gate. A downstream code write or operator reject starts a new convergence and resets `gate_ran`; a docs-allowlisted, disjoint write does not. This follows legacy `execution.md` §Step 3.4 single-pass rule while intentionally tightening §Verdict handling for MEDIUM (R12-4 R1 M1/R2 M2).

“Controlled SKIP” in lifecycle mode recognizes **only** `skipped-by-config`: every path in the frozen candidate changed/closure set (including deletion, rename and mode change) must match saved legacy skip globs (`execution.md` §Skip rule), and the coordinator records matched paths, pattern set, convergence ID and reason. Runtime error/timeout, auth/limit failure, unresolved plugin/schema, missing gate or model-declared skip HOLD with an unspent gate; resume retries when cause clears. `--adversarial-gate off` is refused at lifecycle start, and a migrated old state with it HOLDs. This is intentionally stricter than legacy §SKIP-reason table and preserves paired-session's fail-closed rate-limit behavior (R13-3 R1 M3). Doc 2 owns exact adapter/receipt checks.

Gate rubric revalidation is **not weakened**. Every mapped blocking gate finding, including MEDIUM under this stricter policy, needs the legacy six-field rubric; incomplete findings stay pending for the normal reviewer to re-assert or drop explicitly. The coordinator never auto-withdraws or mints EXEC while one is pending. Complete blockers enter repair; the normal reviewer closes them with an explicit disposition, the sole single-pass-gate exception to source-role re-review. See `execution.md` §Gate rubric revalidation and R12-4 R2 M2.

One blocking taxonomy applies across roles: coordinator `CRITICAL`, `MAJOR`, `SECURITY`, or `security=true` at any severity blocks. Gate and specialist native `CRITICAL/critical→CRITICAL`, `HIGH/high→MAJOR`, `MEDIUM/medium→MAJOR`, `LOW/low→MINOR`; unknown labels HOLD rather than become advisory. MAJOR and MEDIUM never default to advisory, and security=true LOW still blocks. Preserve original labels in receipts (R12-4 R1 M3; R13-3 R1 M1).

Lifecycle activation is an explicit frozen project-config switch, off by default until **all** stage handlers and isolation checks exist (R12-4 R1 M10). Normal EXEC approval goes to FINISH and then POLISH-Q, without entering legacy `start_polish_or_done`. Saved `skip_quality_polish=true` takes precedence and records a no-op POLISH-Q while still running DOCS/SECURITY. Legacy `--polish-round on|off` is deprecated (removed in 3.0.0; ignored). `resume --polish` is rejected for every lifecycle state. Existing `phase=EXEC` with `polish.active`/`polish_round` is legacy POLISH, not POLISH-Q evidence; migration invalidates that polish receipt. Migrated legacy DONE/ACCEPTED cannot enter DELIVERY/CLOSE: explicit migration verifies current EXEC reviewer/gate evidence or reopens EXEC, then runs all new stages, SECURITY and acceptance. No old receipt is relabeled (R12-4 R1 M2).
